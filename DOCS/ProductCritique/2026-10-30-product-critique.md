## Findings (most severe first, max 8)
- [High] 717 Google-Maps-scraped places live in production as `verified: true` — `scripts/oneoff/revert_google_places.js` (on main, never run, not even as a dry run); `app/lib/features/poi_directory/domain/places_query.dart:141` — Google Maps Platform terms forbid scraping and storing Maps content. The "verified only" filter actually promotes these places as trusted, and the README sells "1,100+ places", which is mostly this scrape. Risks: a takedown or a ban on the Google account that also holds Firebase. — evidence: `HANDOFF_Document.md:68,300-301`; `needs_attention.md:116` is still unchecked after 11 days; the importer only writes `verified: false` for new runs (`import_google_places.js:170`), and the production docs were never fixed.
- [High] Known rule holes are published but not deployed — `firestore.rules` (sweep B1-B9) — the repo is public, and PR #98 and `security_sweep_2026-10-30.md` describe each hole: comment counter driven below zero, inbox flooding and pinning via notifications, unvalidated public routes, follow/roster shape. Production still runs the 2026-10-29 rules. — evidence: the sweep doc's "The fixes are public in the merged diff, so deploy the rules soon"; GitHub #97 is open.
- [High] No distributable current build — the README's "Real riders are testing a signed Android build" is stale: APKs were removed from releases and Play internal has an August build. So every fix and feature since then (reads §104.1, App Check gate, moderation, 2026-10-29 lanes) reaches 0 riders. — evidence: `HANDOFF_Document.md` "Release" section; public Play URL 404.
- [High] Spark read quota caps the app at about 18 daily active riders — `DOCS/Handoff for agents and Todos/issues_open.md:780` — reads run out first. The fixes (§104.1 places cache, §104.2 shared positions doc, §104.3 vote query) are on main but in no released build. §104.4 is not done, and group rides double their writes during the dual-write period. The app doesn't seem to display these profile fields today (only forum counts), so the impact is cosmetic. Either drop them from the allow-list or bound them.
